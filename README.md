# 同窗

校园论坛：先注册，再绑定一份或多份学信网学历，按学校或学校等级交流。

## 启动

Python 3.11+，Django 5.2 LTS + 模板/HTMX + SQLite + WhiteNoise，无前端编译步骤。

当前环境已经安装依赖并迁移，直接启动：

```bash
.venv/bin/python manage.py runserver '[::]:8017'
```

打开 <http://127.0.0.1:8017/>。旧用户、学历和帖子已按要求清空，需重新注册。

新环境：

```bash
python3 scripts/setup.py
.venv/bin/python manage.py runserver '[::]:8017'
```

初始化会创建虚拟环境，安装 `requirements.lock`，生成本地密钥，迁移数据库并收集静态资源。初始只包含学校等级、学校目录与五个基础话题。需要独立开发演示数据时，可自行执行 `manage.py seed_demo`；演示账号仅在 DEBUG 模式可用。

## 账户与学历

- 注册仅需用户名和密码，昵称可选，不要求学历。
- 未绑定学历的账号与游客拥有相同内容和参与权限：只能阅读“所有人”帖子，不能发帖或回复。
- 登录后在设置中添加学历，支持学籍报告和学历备案表。
- 一个账号可以绑定多份，所有绑定学校都算本校，不校验多份证明是否同名。
- 相同学历重新上传会更新原记录，不覆盖其他学历。
- 任意一份学历符合阅读或回复范围即可，无需选择单一校园身份。

## 三种发帖权限

| 模式 | 阅读 | 回复 |
| --- | --- | --- |
| 所有人 | 任何人，包括游客、未绑定账号 | 所有已绑定学历的登录账号 |
| 仅本校 | 与作者当前任意一所绑定学校有交集 | 同样要求学校有交集 |
| 等级区间 | 任意绑定学校的等级落在阅读区间内 | 任意绑定学校的等级落在回复区间内 |

区间模式使用双滑块分别设置阅读和回复范围，两段区间都须包含作者任意一所学校的等级，且 `阅读下限 ≤ 回复下限 ≤ 回复上限 ≤ 阅读上限`。服务端表单检查包含本校和范围关系，数据库约束同时保证区间顺序与回复包含关系。游客阅读开关和作者逐校选择已取消。

学校等级由低到高：

1. 专科
2. 普通本科
3. 双一流非211
4. 211非985
5. 其他985
6. 华五：复旦、上海交大、南京大学、浙江大学、中国科大
7. TOP2：北大、清华

等级是站内分类，由管理员维护。内置 582 所本科院校作为初始目录，来源见 [目录说明](accounts/data/NOTICE.md)。未收录学校绑定后创建为未分级；其用户仍可参与公开和同校讨论，分级后才能参与等级区间。目录不是全国完整学校名录，管理员可以添加专科等学校并补充分级。

## 首页偏好

读者可以要求首页推荐的**阅读权限完整覆盖**某个等级区间。例如设置“普通本科至 TOP2”，只推荐“所有人”以及阅读范围包含整段区间的帖子。“仅本校”限制了其他学校，不覆盖整个等级，开启该偏好后也会隐藏。

只作用于发现、关注和同校推荐；搜索、话题、个人主页、收藏、通知和直达链接仍按作者权限判断。帖子权限与学校等级均使用当前值，不记录历史限制。

## 防止学历重复绑定

只用 PDF 文件摘要或在线验证码无法识别同一学历：重新下载、续期、毕业后的报告都可能变化。因此核验官网内容一致后，生成多种稳定标识：

- 证书编号/补证编号：学校 + 编号。
- 学号：学校 + 学号 + 规范化层次。
- 缺少编号的报告兜底：学校 + 姓名 + 出生日期 + 入学日期 + 规范化层次。

同一报告可生成多个别名。学籍与学历报告有共同稳定标识时归入同一学历。专业、学籍状态、预计毕业日期、更新日期、验证码均不参与去重。

标识使用专用密钥计算 HMAC-SHA256，数据库只保存指纹，不保存这些身份字段的原文。指纹是全局主键；绑定事务检查既有归属，新增指纹时依靠唯一约束拦截并发冲突，冲突会回滚整份绑定。不同姓名的多份学历照常可以绑定到同一账号。网站未提供解绑或跨账号转移入口。

没有官方稳定编号时，这种兜底无法完美识别改名、出生信息更正、学校更名、层次变更或极少数同名同生日记录；不同版式若缺少共同字段，也可能需要人工关联。它确保被识别为同一记录的学历不能归属多个账号，不等于核验了上传者本人。

**`EDUCATION_IDENTITY_KEY` 必须长期固定，并与数据库一起备份、迁移。** 不要更换它后继续使用原数据库，否则新旧指纹无法对应。它与可单独轮换的 `DJANGO_SECRET_KEY` 分开保存，初始化脚本不会替换已有非空密钥。

## 报告核验

上传有效的学信网原版文字 PDF，最大 5 MB。先提取原字段，再 HTTPS 查询学信网公开验证码页，双向比对全部正文字段、报告类型、验证码和更新日期，全部一致才绑定。

只忽略排版空白、已知标签别名与等价日期格式；原始提取值保留在独立命令结果中。字段缺失、未知行无法完整解析、查询超时或官网要求人工验证都不会通过。不处理验证码或绕过访问限制。

```bash
.venv/bin/python verify_report.py "report/你的报告.pdf" --output report/verification.json
```

退出码 `0` 全部一致，`1` 字段不同，`2` 读取或查询失败。只有 `verified` 为真后才使用 `education` 分配权限。所提供的学籍 PDF 已实样核对通过；校友备案表已有解析支持，尚缺真实样本核对版式。

论坛核验后删除临时 PDF。独立命令的完整 JSON 含报告个人信息，保留在本地即可。`report/`、`.env` 和 `var/` 已忽略。

## 其他功能与结构

包含 Markdown 发帖/预览/编辑/删除、楼中楼回复、采纳、赞同/不赞同、收藏、话题关注、搜索、通知、个人主页与管理后台。Markdown 经 nh3 清理，修改使用 POST 与 CSRF，所有内容入口复用同一阅读权限查询。

帖子和回复在保存时渲染一次 Markdown，缓存清理后的 HTML 与纯文本摘要；列表只读取摘要，不读取正文。修改 `forum/text.py` 的渲染规则后，执行 `manage.py render_markdown` 重新生成。

## 界面

- 顶部导航加居中双栏：信息流在左，侧栏放校园、话题与站点信息；窄屏收起侧栏，手机端使用底部标签栏。
- 颜色、字号、圆角集中在 `static/app.css` 顶部的设计令牌里。正文字号不小于 12px，文字对比度满足 WCAG AA。
- 深色模式默认跟随系统，也可在页头切换并记在本机；`<head>` 中的内联脚本在首屏绘制前确定主题，避免闪烁。
- 赞同、收藏、关注、回复、评论点赞、采纳、删除回复和“加载更多”都用 HTMX 局部刷新；没有 JavaScript 时，同样的表单和链接会整页提交。
- 回复按一级回复展示，楼中楼平铺在所属回复下并标注回复对象。编辑器支持常用格式按钮，`Ctrl/⌘ + Enter` 发布，`Ctrl/⌘ + K` 搜索。
- 图标集中在 `static/icons.svg`，模板用 `{% icon 'name' %}` 引用，头像用 `{% avatar user %}`，两个标签已注册为模板内置标签。

```text
accounts/          账户、学校等级、多学历、去重与认证
accounts/data/     初始学校目录与来源
forum/             帖子、权限查询、讨论、通知
campus/            Django 配置、路由、WSGI
templates/         页面与 HTMX 局部片段
static/            设计令牌与深浅色样式、原生 JS、SVG 图标集
verify_report.py   独立报告提取与官网比对
scripts/setup.py   环境初始化
```

业务数据库为 `var/db.sqlite3`，启用 WAL 以免读请求被写入阻塞；备份时使用 `sqlite3 var/db.sqlite3 ".backup 'backup.sqlite3'"`，不要只复制主文件。创建管理员后访问 `/admin/`，维护学校及等级：

```bash
.venv/bin/python manage.py createsuperuser
```

## 单机部署

设置 `.env` 中生产密钥、固定的学历去重密钥和 `DJANGO_DEBUG=0`。Django 接受任意 Host；通过 HTTPS 反向代理访问 Gunicorn，可信代理覆盖 `X-Forwarded-Proto` 时设置 `DJANGO_TRUST_PROXY=1`。

```bash
.venv/bin/python manage.py migrate --noinput
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/gunicorn campus.wsgi:application --bind '[::]:8017' --workers 2 --timeout 60
```

WhiteNoise 提供带哈希文件名的压缩静态资源；请求体上限应允许 5 MB PDF 加表单字段。配置检查使用 `manage.py check`。测试集中于 `forum/tests.py`，覆盖内容安全、演示账户限制、Markdown 缓存与 HTMX 讨论区刷新。
